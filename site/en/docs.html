Documentation

LimeControl — the guide

LimeControl is an app for managing LimeSurvey instances through the official RemoteControl 2 API (JSON-RPC, remotecontrol_handle). It runs as a native mobile app for iOS and Android (with no account and no CORS restrictions), in the browser on a phone or a computer — also installed as a PWA — and on your own server. It is the same code everywhere.

Requirements: LimeSurvey 3.x, 5.x, 6.x or 7.x with the JSON-RPC interface enabled, and a LimeSurvey account with the right permissions. In the app.limecontrol.eu service you sign in with a Google account; a self-hosted installation uses an access key.

The app is part of an open-source toolkit that also includes survey themes, survey templates and deployment kits. App version described in this guide: 1.1.0.

Quick start

  1. In the LimeSurvey admin panel enable the JSON-RPC interface (instructions).
  2. Open app.limecontrol.eu and sign in with a Google account.
  3. On the Instances tab add a profile: a name, the server address (for example https://surveys.yourcompany.com is enough), the user name and the password.
  4. Click Connect. The app fetches the instance name and the list of surveys.
  5. Go to the Surveys tab. If the instance is empty, import your first survey from the template library.

If you get a connection error, check the RPC log panel and the CORS and HTTPS section.

Installing on a phone

Mobile app: the free LimeControl app for iPhone, iPad and Android. Get it for free: Google Play. The App Store version is waiting to be published. See Mobile app for details.

PWA: the web version installs without an app store and updates itself.

  • Android (Chrome, Edge): the Install PWA button in the app, or the browser menu → Add to Home screen.
  • iPhone / iPad (Safari): Share → Add to Home Screen.
  • Desktop (Chrome, Edge): the install icon in the address bar.

When the device goes offline, the app shows an offline indicator. Survey operations need access to the LimeSurvey server.

You can switch the interface language (English or Polish) in the app header; the choice is remembered on the device.

Enabling the API in LimeSurvey

  1. Log in to the LimeSurvey admin panel as a superadministrator.
  2. Go to Configuration → Global settings → Interfaces.
  3. In the RPC interface enabled field choose JSON-RPC.
  4. The Publish API on /admin/remotecontrol option is not required — set it according to your security policy. Click Save.

The default API address:

# friendly URLs enabled
https://your-instance.com/index.php/admin/remotecontrol

# friendly URLs disabled
https://your-instance.com/index.php?r=admin/remotecontrol

In the app the base address is enough — the /index.php/admin/remotecontrol path is added automatically.

LimeSurvey account permissions

The account used in a connection profile should have these permissions:

AreaPermissionsUsed for
SurveysView/Read, Update, Create, ActivateListing, activation, dates, closing, copying, template import, changing the theme
Participants / tokensManagementToken table, invitations, reminders
ResponsesExportDownloading results as CSV / XLS / JSON

Authentication plugin: leave Authdb for ordinary LimeSurvey accounts or enter the name of the plugin you use, for example AuthLDAP.

Good practice: create a separate LimeSurvey account just for LimeControl, with permissions limited to the surveys it needs.

Connection modes

Each instance profile has its own connection mode:

Direct (default)

The browser sends JSON-RPC requests straight to the LimeSurvey server. No data passes through the LimeControl servers. It requires HTTPS and CORS headers on the LimeSurvey side.

Server relay

When you cannot change the LimeSurvey server configuration, choose Server relay (CORS workaround) in the profile. Requests then go to /api/rpc-relay on the app server and from there to LimeSurvey.

  • The relay works for signed-in users only and has a request limit.
  • It connects over HTTP/HTTPS only, does not follow redirects and, in the public service, rejects internal network addresses (localhost, 10.x, 192.168.x and so on).
  • On a self-hosted installation private addresses are allowed by default — LimeSurvey may live on the same network.

In relay mode the user name, the password and the survey data pass through the app server (they are not stored there). Use it only when direct mode is not possible.

Native app

The LimeControl mobile app connects to the server through the system's native networking layer, so it is not subject to CORS restrictions and needs no relay.

CORS and HTTPS

The app runs over HTTPS, so the LimeSurvey server has to be reachable over HTTPS as well — browsers block requests to http:// addresses (mixed content).

The server also has to return CORS headers, including for OPTIONS preflight requests. Instead of * you can enter the specific app domain.

Apache (.htaccess or VirtualHost)

Header always set Access-Control-Allow-Origin "https://app.limecontrol.eu"
Header always set Access-Control-Allow-Methods "POST, OPTIONS"
Header always set Access-Control-Allow-Headers "Content-Type, Accept"

Nginx

add_header Access-Control-Allow-Origin "https://app.limecontrol.eu" always;
add_header Access-Control-Allow-Methods "POST, OPTIONS" always;
add_header Access-Control-Allow-Headers "Content-Type, Accept" always;

If you have no access to the server configuration, use the server relay mode or the mobile app.

LimeSurvey 7.x

In the profile form choose the version LimeSurvey 7.x (UTC dates + new error codes) (the Automatic option keeps the default RC2 behaviour). The app then:

  • converts the startdate and expires dates and the scheduler times to UTC,
  • recognises the new RemoteControl 2 error codes and shows readable messages,
  • handles the new field identifiers in the get_fieldmap inspector.

In LimeSurvey 7.9+ you can enable a server-side log of API calls in application/config/config.php:

'config' => array(
    'rpc_log' => true,
)

The log goes to tmp/runtime/remotecontrol.log; passwords and session keys are masked in it.

Instances

The Instances tab keeps the LimeSurvey server profiles. In the app.limecontrol.eu service the profiles are stored in the cloud (Cloud Firestore) and tied to your Google account, so they are available on every device. In the mobile app and on a self-hosted installation the profiles stay on the device and in the browser respectively.

  • Search and filter profiles by name, address, user or login plugin, and by connection mode (All, Direct, Relay).
  • A LimeSurvey version setting for each profile.
  • RPC log — a list of API calls with response times and error diagnosis (for example CORS).

Surveys

A survey list with search and an All / Active / Inactive filter. The quick-action menu next to each survey lets you:

  • Activate a survey (activate_survey), optionally together with its token table (activate_tokens).
  • Set the availability window — the start and end dates (set_survey_properties).
  • Close an active survey.
  • Copy a survey (copy_survey).
  • Jump to the schedule or the participants of the selected survey.

The survey details also hold the Link, CAPI mode and theme and CATI / CAPI fieldwork cards.

Survey template library

The Template library button on the Surveys tab opens a list of ready-made questionnaires — the same ones you can download from the Survey templates page. Every template comes with English and Polish language versions, conditional logic and the invitation and reminder texts.

  1. Connect to an instance and open Surveys → Template library.
  2. Narrow the list down by category. Each template shows its fieldwork modes (CAWI, CATI, CAPI), the number of questions, the estimated completion time and the suggested theme.
  3. Click Import. The app sends the .lss structure file with the import_survey method; a new, inactive survey appears in the instance and is selected in the list straight away.
  4. Adjust the questions in the LimeSurvey admin panel, then activate the survey in the app.
  • The templates are bundled with the app, so the library also works on a self-hosted installation without internet access.
  • Before importing, the app checks the file's SHA-256 checksum against the template catalogue.
  • A template points to a LimeControl theme (for example lc_professional). If the theme is not installed, LimeSurvey uses its default theme — you can change it later in the Link, CAPI mode and theme card.
  • The account needs the permission to create surveys.

The templates are released under CC0 1.0 — you may change and use them freely, including commercially.

Link, QR code and theme

The Link, CAPI mode and theme card in the survey details gathers the things you would normally open the admin panel for.

Link for respondents

  • The public address of the survey in the chosen language — with the Copy link, Share (the system share sheet on a phone) and Open buttons.
  • The QR code is generated in the browser; the address is not sent to any external service. Scan it with a phone or put a screenshot on a poster or a slide.
  • For an inactive survey the app reminds you that the link starts working after activation.

Survey theme

Choose one of the LimeControl themes and click Save theme. The app sets the template property and reads it back immediately — if the theme is not installed on the server, you get a message naming the theme the survey actually uses.

The themes have to be installed in LimeSurvey first: Configuration → Themes, the Upload & install button (instructions).

CATI and CAPI interviews

LimeControl helps you get a survey ready for an interviewer — on the phone (CATI) or in the field (CAPI). The questionnaire and the responses stay in LimeSurvey.

CAPI mode in the app

  • Start an interview opens the survey with the newtest=Y parameter, so always as a new, empty interview — without the previous respondent's answers.
  • Switch on the interview loop sets automatic redirection in the survey (autoredirect) and the end URL of every language version so that the survey starts the next interview by itself when one ends. Handy for an interviewer and for a kiosk-style station.
  • The same button switches the loop off; the app then restores the ordinary end of the survey.

CAPI mode in the app needs an internet connection — the interview takes place in the LimeSurvey survey. Offline work is provided by the interviewer app of the StrefaAnkiet platform, which the free plugins connect to LimeSurvey.

Interviewer themes

  • LimeControl CATI — a wide layout for a computer screen and keyboard shortcuts: 1–9 and 0 select the consecutive answers, Ctrl+Enter goes to the next page, Ctrl+Shift+Enter goes back. The shortcuts can be turned off with the switch next to the navigation.
  • LimeControl CAPI — a larger font and touch targets at least 56 px high, with the navigation stuck to the bottom of the screen.
  • In every LimeControl theme a question with the CSS class lc-interviewer is marked as text to read out or a field completed by the interviewer (about the interviewer mode).

Interview skeletons

The template library has two skeletons ready to build on:

  • CATI interview — an opening script, the call outcome (interview, callback, refusal), consent, a question block, demographics and interviewer notes. It includes participant fields (phone, contact status, callback time, note), which the app creates together with the participant table (Participants).
  • CAPI interview — interview details (interviewer, sampling point, place), consent and screening, a question block with a ranking, demographics and the interviewer's post-interview observations.

Interviewer assignments, a call queue, VoIP telephony, callbacks and quotas across modes are provided by the StrefaAnkiet platform. The free plugins connect it to LimeSurvey, and the fieldwork status shows up in the CATI / CAPI fieldwork card.

Statistics and export

Each survey has a summary of responses and tokens (get_summary) with charts, and two surveys can be compared side by side.

Responses are exported (export_responses) to:

  • CSV — for spreadsheets and analysis tools,
  • Excel (.xls),
  • JSON — for further processing.

The column inspector (get_fieldmap) shows what the fields are called in the export — both in the older SGQA format and in the new LimeSurvey 7 format.

Scheduler

Schedule an operation for a chosen day and time. The job is run by the app server, so it works even after you close the app on your phone.

OperationWhat the server does
Activate the surveyactivate_survey, optionally activate_tokens and the start and end dates (set_survey_properties)
Close the surveysets the expires end date to the moment the job runs
Send invitationsinvite_participants — to participants who have not received an invitation yet
Send remindersremind_participants — to invited participants who have not completed the survey

Every job starts with get_session_key and ends with release_session_key:

get_session_key
  → activate_survey        # or set_survey_properties / invite_participants / remind_participants
  → activate_tokens        # optional, on activation
  → set_survey_properties  # optional: startdate, expires
  → release_session_key

Invitations and reminders

  • The survey has to be active and have a participant table. LimeSurvey sends messages in batches — the server repeats the call until the queue is empty.
  • For reminders you can set the minimum number of days since the last message and the maximum number of reminders per person.
  • Repeat every (days) and Number of repeats create a series of reminders: after a successful run the server queues the next job.
  • If no message went out at all (for example because of a wrong SMTP configuration in LimeSurvey), the job ends with an error, not a “success”.

How the queue works

  • The queue is checked every 15 seconds.
  • Each job has a detailed log of its RPC steps.
  • Run now executes a job immediately — useful for testing.
  • A scheduled job can be cancelled or removed from the history.
  • The password needed to log in is stored in the queue encrypted (AES-256-GCM) and removed once the job has run or been cancelled. A reminder series keeps it until the last repeat.
  • The time is saved together with the time zone of your device; for LimeSurvey 7.x profiles dates are sent to the server in UTC.

An in-app notification tells you the result of a job (success or error).

Participants and email templates

Participants (tokens)

  • Initialise the token table with one tap (activate_tokens).
  • If the survey defines extra participant fields — like the “CATI interview” template — tick Create the fields from the template and the app creates them together with the table.
  • A participant list with a filter for unused tokens.
  • Adding and removing respondents.

Template editor

Edit the subject and body of the invitation and the reminder for each survey language. The editor previews the message with sample data and inserts placeholders quickly:

{FIRSTNAME} {LASTNAME} {EMAIL} {TOKEN} {SURVEYURL} {OPTOUTURL} {SURVEYNAME}

The Save and send invitations and Save and send reminders buttons save the template and send the invitations (invite_participants) or reminders (remind_participants) straight away. Afterwards the app shows how many messages went out, how many failed and how many are still waiting. To send at a specific time, use the scheduler.

Emails are sent using the mail configuration of your LimeSurvey server. Check it in LimeSurvey before the first mailing.

StrefaAnkiet connector (beta)

If a survey is linked to a study on the StrefaAnkiet platform (through the free plugins for LimeSurvey), the CATI / CAPI fieldwork card in the survey details shows the fieldwork status — without opening the platform panel. The connector and the plugins are free of charge; you need a StrefaAnkiet account, which is a paid service.

  1. In StrefaAnkiet create an access key with the fieldwork.read and cati.read scopes: Settings → Integration centre → External application access.
  2. In LimeControl open the survey, expand the CATI / CAPI fieldwork card and enter the platform address (for example https://app.example.com) and the key.
  3. Click Connect and find the study. The app looks up the study linked to the survey ID (SID). If it finds none, enter the project and study numbers by hand.
ModeWhat the app shows
CAPIInterviews confirmed in LimeSurvey, interviews from the interviewer app, interviewer assignments and their progress against the target, fieldwork blockers
CATIThe number of cases in the queue, unassigned cases and cases that need attention
  • Read-only. The connector changes nothing in the study. Requests pass through the app server (/api/strefaankiet), which lets through only read requests to a short list of the platform's API addresses.
  • The key stays with you. It is kept only in the memory of the open tab and disappears when you close it; the server neither stores nor logs it. The browser remembers only the platform address and the link between the survey and the study.
  • The assignment list requires a key with the study coordinator role.

The connector is in beta: it has been checked against the platform's API, but not in every study set-up. Please report feedback in the GitHub issues.

Mobile app

LimeControl for iOS (iPhone and iPad) and Android is the same app in a native shell — free and open source. Get it for free: Google Play. The App Store version is waiting to be published.

  • No account. You do not sign in with a Google account or an access key. Server profiles are stored on the device only, and the app never stores LimeSurvey passwords.
  • Direct connection. The app connects to the LimeSurvey server from the device, without CORS headers and without the relay.
  • Sharing and export. The survey link and the result files go to the system share sheet — save them on the device or send them on.
  • Encryption. On Android the server has to be reachable over HTTPS. On iOS an unencrypted connection is allowed only to addresses on the local network.
  • Theme. The app follows the system's light or dark appearance until you pick one with the switch in the header.

The scheduler in the mobile app

Scheduled jobs are run by a server, and the mobile app has none of its own. If you run a self-hosted LimeControl, connect it on the Instances → Server tab: enter the server address, then the access key. The Schedule tab then works as in the browser, and jobs run even when the phone is off. Instance profiles still stay on the device.

The app.limecontrol.eu service (Google sign-in) is not supported in the mobile app yet.

LimeControl on your own server

You can run the app yourself in a Docker container — without a Google account and without Firebase. You sign in with an access key, the instance profiles are saved in the browser, and the scheduler and the relay run in your container.

The app.limecontrol.eu serviceSelf-hosted installation
Sign-inGoogle accountaccess key
Instance profilesCloud Firestore, synced between devicesbrowser storage, without passwords
Schedulerthe service's serveryour container, passwords encrypted in the data volume
RPC relaypublic addresses onlyprivate networks too

Quick start

git clone https://github.com/lukasz5/LimeControl.git
cd LimeControl/deploy/selfhost
cp .env.example .env
# enter your own key (min. 16 characters), e.g. the output of: openssl rand -base64 24
nano .env
docker compose up -d --build

The app runs at http://127.0.0.1:8080. If you leave LIMECONTROL_ACCESS_KEY empty, a key is generated on first start — read it with docker compose logs app. Then publish the app through your reverse proxy with a TLS certificate.

Outside localhost use HTTPS. Without it the browser will not install the PWA, and the access key and passwords would travel in clear text.

Next to the LimeSurvey stack

If LimeSurvey runs from the limesurvey-stack kit, LimeControl can use the same Traefik and Let's Encrypt certificates:

# in .env set LIMECONTROL_DOMAIN, and STACK_NAME if you renamed the stack
docker compose -f compose.yaml -f compose.with-stack.yaml up -d --build

In LimeControl add an instance with the address http://limesurvey:8080 and the Server relay mode — the requests then stay inside the Docker network. If Force HTTPS is switched on in LimeSurvey, use the public https:// address of the instance.

Environment variables

VariableDefaultDescription
AUTH_MODElocal in the kitlocal (access key) or firebase (requires a firebase-applet-config.json file)
LIMECONTROL_ACCESS_KEYgeneratedthe sign-in key, at least 16 characters
LIMECONTROL_SECRETthe data/secret.key filekey material for encrypting scheduled-job passwords

There is one access key for the whole installation — this mode is meant for one person or a trusted team. Updating, backups and running without Docker are described in the kit's README.

Your own LimeSurvey instance

If you do not have a LimeSurvey server yet, use the ready-made, hardened Docker stack: limesurvey-stack (LimeSurvey 7, PHP 8.3, MariaDB 11.4, Traefik with Let's Encrypt, daily backup).

git clone https://github.com/lukasz5/limesurvey-stack.git
cd limesurvey-stack
sudo ./install.sh

After installing, enable JSON-RPC (Enabling the API) and add the instance in LimeControl. The installer walks you through the configuration in the terminal, and running sudo ./install.sh again opens a management menu (backup, restore, logs, updates). Details are in the stack's README.

Would you rather have someone do it for you? We deploy and maintain survey servers built on LimeSurvey software — write to info@strefabadan.pl or get in touch through strefabadan.pl.

Security and privacy

  • Google sign-in (Firebase Authentication) protects access to your profiles; on a self-hosted installation an access key with a limit on sign-in attempts plays that role.
  • Server profiles are stored in Cloud Firestore; the database rules allow only the account owner to read and change them. In the mobile app and on a self-hosted installation the profiles stay on the device and in the browser respectively.
  • LimeSurvey passwords are not stored in Firestore or in localStorage. The “Remember the password for this session only” option keeps them solely in the memory of the open tab.
  • Direct mode — survey data goes straight from the LimeSurvey server to your browser.
  • The relay and the StrefaAnkiet connector require sign-in, have request limits, connect over HTTP/HTTPS only, do not follow redirects and pin the checked IP address (protection against SSRF and DNS rebinding).
  • Scheduler — the password needed to run a job is encrypted (AES-256-GCM) and kept on the app server only until the job has run or been cancelled.

The privacy policy describes what data we process and why. Please report a security vulnerability privately — the SECURITY.md file in the repository explains how.

Troubleshooting

SymptomCause and fix
CORS error / Failed to fetchNo CORS headers on the LimeSurvey server. Add them (examples) or switch the profile to the server relay.
Mixed content blockedThe LimeSurvey server runs over http://. Enable HTTPS on the server.
Invalid user name or passwordCheck the user name, the password and the authentication plugin (Authdb, AuthLDAP).
404 or an HTML response instead of JSONThe JSON-RPC interface is disabled or the API address is different — enter the full path with ?r=admin/remotecontrol.
No permissionThe account lacks the required permissions for that survey.
Dates shifted by a few hoursSet the LimeSurvey 7.x version in the profile (dates in UTC) or check the server time zone.
The relay rejects the server addressIn the public service the relay does not connect to internal network addresses. Use direct mode, the mobile app or a self-hosted installation.
The survey uses a different theme than the one chosenThe theme is not installed in LimeSurvey. Upload the theme ZIP file (instructions) and save the theme again.
Invitations are not going outCheck that the survey is active, has a participant table and that mail is configured correctly in LimeSurvey. The error details are in the scheduled job's log.

The details of every call are in the RPC log panel on the Instances tab.
