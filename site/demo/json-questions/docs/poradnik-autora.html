Jak zbudować ankietę zależną i odczytać jej wynik

W przykładzie Gotowość sprzętu do zajęć respondent wskazuje miejsca, wybiera urządzenia w każdym miejscu i wpisuje ich stan naładowania. Przy 20% lub mniej podaje, co zrobi przed zajęciami. Ten sam tablet w dwóch miejscach można ocenić osobno. Łańcuch składa się z jednego zwykłego pytania LimeSurvey i trzech pytań typu Bardzo długi tekst (U).

Odtwórz odpowiedź wzorcową

  1. Zainstaluj wtyczkę i trzy motywy z zestawu 0.2.0. W LimeSurvey w sekcji tworzenia ankiet wybierz import pliku LSS i wskaż equipment.lss. Otwórz podgląd całej ankiety, aby sprawdzić kolejność pytań. Do próby eksportu aktywuj ankietę testową i przejdź przez jej adres dla respondentów.
  2. Zaznacz Biblioteka i Pracownia. W bibliotece wybierz Tablet, w pracowni Aparat. W kolejnym pytaniu zobaczysz dwa wiersze.
  3. Wpisz 0 dla tabletu i 100 dla aparatu. Dla tabletu wpisz dokładnie Naładuję tablet. i zakończ ankietę. Pytanie o działanie pojawi się tylko przy tablecie.
  4. W ustawieniach administracyjnych ankiety wybierz Narzędzia → LimeControl JSON · Eksport CSV. W pliku odszukaj swój response_id. Powinno przypadać na niego pięć rekordów, po dwa dla DEVICES i CHARGE oraz jeden dla PLAN. Porównaj kody, ścieżki i wartości z plikiem wzorcowym.

W następnej próbie wpisz 20 dla tabletu. Wiersz z planem działania nadal będzie widoczny. Wartość 21 ukryje ten wiersz. 101 przekroczy dopuszczalny zakres samego pytania o baterię. Próg dopytania i zakres poprawnych odpowiedzi ustawia się niezależnie.

Skonfiguruj ten sam przebieg we własnej ankiecie

Dodaj pytania w podanej kolejności. W menu ankiety otwórz Narzędzia → LimeControl JSON · Edytor, wybierz odpowiednie pytanie U, ustaw źródło i zapisz. Źródłem może być wcześniejsza natywna lista jednokrotnego wyboru (typ L lub !), pytanie wielokrotnego wyboru (M lub P) albo wcześniejszy blok zestawu.

Kod Typ lub motyw Co ustawić
PLACES Natywne pytanie wielokrotnego wyboru (M) Dodaj podpytania LIBRARY („Biblioteka”) i STUDIO („Pracownia”).
DEVICES U → Wybór dla każdej pozycji Wskaż źródło PLACES. Dodaj opcje TABLET i CAMERA z typem „Wielokrotny wybór”.
CHARGE U → Tabela z wcześniejszych odpowiedzi Wskaż DEVICES. Dodaj kolumnę BATTERY, etykietę „Naładowanie (%)” i typ „Liczba”. Zaznacz „Wymagaj wartości”, ustaw minimum 0 i maksimum 100.
PLAN U → Pytanie uzupełniające Wskaż CHARGE. Dodaj wymaganą kolumnę tekstową ACTION z etykietą „Co zrobisz przed zajęciami?”. Dodaj poniższą regułę.

Dla PLAN wybierz działanie Pokaż, cel *, pole source · BATTERY, operator Co najwyżej i wartość 20. Cały wiersz ma się pojawić, gdy bateria danego urządzenia wskazuje najwyżej 20%. W zapisanej definicji reguła ma taką postać.

{
  "effect": "show",
  "target": "*",
  "when": { "field": "source.BATTERY", "op": "lte", "value": 20 }
}

Wybór pojedynczy dopuszcza jedną aktywną opcję typu single w wierszu. Wybór wielokrotny pozwala zaznaczyć kilka opcji. Opcja oznaczona jako Wyłączna usuwa pozostałe aktywne wpisy w swoim wierszu. Pole Komentarz wymaga komentarza po użyciu danej opcji. Aby wymagać go warunkowo, wybierz działanie Wymagaj komentarza i określ warunek. Przykład wyboru „Inne” z komentarzem znajdziesz w ankiecie o pracach terenowych.

Z czego składa się warunek

Pole Jak jest oceniane
source.BATTERY Wartość kolumny BATTERY w źródłowym wierszu tego urządzenia. Wybierasz kolumny z definicji poprzedniego bloku.
self.KOD Wartość wskazanej kolumny w bieżącym wierszu. Przydaje się do odkrywania kolejnego pola w tym samym pytaniu.
source.count Łączna liczba wierszy utworzonych przez źródło dla tego bloku. W macierzy przykładowej odpowiedzi wynosi 2.

Operatory liczbowe obejmują gt (>), gte (≥), lt (<) i lte (≤). eq oznacza równość. selected sprawdza, czy dana komórka ma aktywną wartość. Wartość liczbowa 0 jest aktywna. Grupą Wszystkie połącz warunki wymagane łącznie, a grupą Dowolny warunki, z których wystarczy jeden. Zaprzeczenie odwraca wynik jednego warunku.

Cel * przy Pokaż oznacza cały wiersz. Przy Wymagaj wartości ten sam cel wymaga co najmniej jednej aktywnej komórki w wierszu. Wybierz kod kolumny jako cel, jeśli zależy Ci na konkretnej komórce. Kilka oddzielnych reguł Pokaż dla tego samego celu wymaga spełnienia wszystkich warunków. Wartości w ukrytych komórkach oraz ścieżki usunięte przez zmianę wcześniejszego wyboru są pomijane w eksporcie.

Granice liczbowe od wersji 0.2.0

W kolumnie typu number obie granice są opcjonalne i włączne. Możesz podać tylko minimum, tylko maksimum albo obie wartości. Minimum i maksimum mogą być równe. Wymagalność ustawiasz osobno. Pole bez granic przyjmuje również wartości ujemne. Przykładowy zapis kolumny wygląda następująco.

{
  "code": "BATTERY",
  "type": "number",
  "label": { "pl": "Naładowanie (%)" },
  "required": true,
  "min": 0,
  "max": 100
}

Odczytaj odpowiedź JSON i CSV

LimeSurvey zapisuje każde pytanie U w jednej kolumnie. Odpowiedź zawiera wersję formatu, rewizję konkretnej definicji i listę wierszy. Dla pytania CHARGE z podanego przykładu zawartość pola jest następująca.

{
  "version": 1,
  "revision": "3439516541d77259",
  "rows": [
    { "path": ["LIBRARY", "TABLET"], "cells": { "BATTERY": { "value": 0 } } },
    { "path": ["STUDIO", "CAMERA"], "cells": { "BATTERY": { "value": 100 } } }
  ]
}

path identyfikuje wiersz. Pierwszy element pochodzi z wyboru miejsca. Blok choice dokłada kod urządzenia podczas tworzenia wiersza następnego pytania. Macierz przekazuje tę samą ścieżkę pytaniu uzupełniającemu. Dzięki temu ["LIBRARY","TABLET"] oznacza ten sam sprzęt w CHARGE i PLAN, niezależnie od języka formularza.

W eksporcie wtyczki każdy rekord odpowiada jednej zapisanej komórce aktywnego wiersza. Odszukaj question_code = CHARGE, column = BATTERY i path = ["LIBRARY","TABLET"]. Wartość value = 0 oznacza rozładowany tablet. Pusty tekst w comment w tym rekordzie jest prawidłowy. W pytaniu PLAN treść „Naładuję tablet.” trafia do value, bo ACTION jest kolumną tekstową. Przykład terenowy pokazuje komentarz w osobnym polu comment. Wzorzec sprzętowy · Wzorzec terenowy

Do interpretacji etykiet pobierz LimeControl JSON · Słownik CSV i połącz go z eksportem po question_code, revision i column. Identyfikator odpowiedzi przydziela Twoja instalacja. Zmiana definicji może zmienić rewizję, w tym po edycji etykiet. Zachowaj dotychczasowe kody przy tłumaczeniu.

Gdy wynik różni się od przykładu

Objaw Co sprawdzić
Edytor nie pokazuje źródła Ustaw źródło przed pytaniem U w kolejności grup i pytań. Sprawdź typ źródłowy oraz zapis konfiguracji wcześniejszego bloku.
Zamiast urządzeń widać puste pytanie Zacznij podgląd od początku ankiety, wybierz miejsce i urządzenie. W podglądzie pojedynczego pytania brakuje wcześniejszych odpowiedzi. W pytaniu PLAN sprawdź też, czy przynajmniej jeden poziom baterii wynosi 20 lub mniej.
Motyw jest niedostępny na liście Wgraj ZIP danego motywu w Motywach pytań. Upewnij się, że w menedżerze wtyczek aktywna jest LimeControlJsonQuestions.
Wartość 101 przechodzi walidację Sprawdź wersję zainstalowanej wtyczki i granice BATTERY. Rozpocznij nową odpowiedź po zmianie definicji, aby przetestować nową rewizję.
CSV zawiera całą strukturę w jednym polu Wybierz Narzędzia → LimeControl JSON · Eksport CSV. Do eksportu wtyczki potrzebujesz obu uprawnień do odpowiedzi w ankiecie, odczytu i eksportu.
Wartość przekracza pojemność pola Sprawdź rozmiar zakodowanego bloku w bajtach. Podziel długie tabele lub komentarze na osobne pytania U. Każdy blok ma limit najwyżej 2 MiB, a pojemność kolumny MySQL oraz szyfrowanie mogą go obniżyć.

Przy aktualizacji z 0.1.0 wykonaj kopię bazy, ankiety i ZIP-ów, a następnie zaktualizuj cztery paczki do tej samej wersji. Istniejące kolumny bez min i max zachowują poprzedni zakres. Aby sprawdzić nową granicę, uzupełnij ją w edytorze i zapisz definicję. Otwórz nową odpowiedź oraz wznów wcześniejszą z zapisanymi wierszami. W eksporcie sprawdź obie rewizje. Zasady odpinania pytań i wyniki testów poszczególnych wydań znajdziesz w instrukcji instalacji i utrzymania.
